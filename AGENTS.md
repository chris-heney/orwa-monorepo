# AGENTS.md

## Learned User Preferences

- When asked to "stage/commit/push/deploy", group only request-relevant work into small logical commits with scoped prefixes (e.g. `strapi: ...`); leave unrelated work unstaged and keep test artifacts (`.playwright-mcp/`, screenshots, editor state files) out of version control.
- "Deploy" includes the server-side step (pull + restart on the production host, or rsync for frontends), not just pushing the image/bundle; follow it with safe, non-destructive production smoke tests when practical.
- Verify frontend changes visually in a headless browser before deploying; a clean typecheck/build alone is not sufficient.
- member-manager login must not hard-fail when user metadata/role fetch fails after a successful JWT auth; fall back to a safe default (e.g. Guest) so users can still get in.
- Do not commit tracked `.env` files that contain secrets (e.g. Mapbox tokens in `grant-map`); GitHub push protection rejects them. Leave secret-bearing and machine-local port/API env tweaks unstaged when they would re-push secret blobs.
- Do not wrap member-manager / Conference Manager admin surfaces with `TermsGate`; terms acceptance belongs on public registration (and similar) flows only. On conference-registration, mount `TermsGate` only when registration is open for the current source (`Online Registration`, or `Kiosk Registration` + `source=kiosk`) — never over the closed/not-open screen.
- New member-manager list/edit pages should use the Media Library–style black `PageHeadingBar` (actions in the bar; Contact-style Back on create/edit), as on Terms and Asset Manager.
- conference-registration sponsorship must be its own wizard step immediately before Billing (not a Type-page toggle); people miss a buried sponsor control. Sponsorships are available to Attendee and Vendor (online when packages exist). Sponsor logo uploads accept web images only (not PDF).
- conference-registration validation must be unmissable (user base skews older): use the shared red toast for step-validation failures everywhere and visibly highlight invalid fields (light red background or bold red rounded outline). Grey checkbox/radio wraps must behave like labels — fully clickable, pointer cursor, subtle darker hover. Never hide an extra solely because it costs $0: free meals still need selectable RSVPs for headcounts, displayed as "Included" (not `$0.00`); render the Extras heading/copy only when the same filtered set contains options. When an Attendee/Vendor ticket has zero extras selected, confirm with a dialog listing the unchecked extras before continuing (No re-highlights them like failed validation).
- In conference-registration TicketModal, Registration Options (Training Type) sits above Contact Details; any training type other than None requires a real email — clear/hide/disable "I do not have an email", and note that email is required for training credit. For Attendee tickets, Company/Organization defaults from the parent registration Organization.
- member-manager summary dashboards (Grant, Membership, Conference): the blue ink-canvas panel must sit flush under the tab bar — square top corners (`borderRadius: "0 0 18px 18px"`) and zero tab-panel padding/margin (no white gutter). The Grant Manager summary is the gold-standard reference when modernizing other member-manager reporting surfaces (Membership Reporting and Conference Manager Summary / Event Command Center were rebuilt to match it). Grant summary metrics say "Reserved" (not "Requested") — Reserved excludes withdrawn/denied statuses — show both application count and dollar amount per metric, hide zero-value widgets, and keep the plain-language glossary. Compact `money(..., true)` must keep a meaningful decimal (`$1.5K` for $1500, never round to `$2K`). FundsExplorer's combined view must be a stacked breakdown of raw requested dollars per category segmented by lifecycle endpoints (Awaiting Approval/Committee/Signature, Denied/Withdrawn, On Hold, Approved, Paid in Part/Full), not grouped Reserved/Approved/Disbursed totals. The user keeps commissioning the same treatment for other legacy surfaces (Training Manager, grant-application app, grant-map) to match Grant Manager / conference-registration quality; when they like multiple design variants, keep all of them behind a compact persisted toggle in the section header (react-admin `useStore`, e.g. `grant.pathwaysVariant` → localStorage `RaStore.*`) instead of stacking them on the page.
- member-manager must look good in BOTH light and dark mode: use theme-aware tokens — summary surfaces use `useSummaryTokens()` from `grant-manager/grants/components/summary/tokens.ts` — and never hardcode light-only colors; verify both modes visually before calling UI work done.

## Learned Workspace Facts

- Strapi backend deploy: `npx nx run strapi:docker-push` (builds and pushes image to GHCR), then `ssh root@admin.orwa.org "cd /var/opt/orwa-monorepo && docker compose pull strapi && docker compose up -d strapi"`. The live compose file is `/var/opt/orwa-monorepo/docker-compose.yml` (not `/var/opt/admin.orwa.org`); the production Strapi container is named `orwa-admin-v5`.
- Frontends deploy as static production bundles rsynced over SSH to WP Engine (`orwa.ssh.wpengine.net`, install `orwa`) under `sites/orwa/`: `member-manager/`, `conference-registration/`, `gapp-map/` (grant-map), `gapp-form/` (grant-application), `associate-directory/`. Avoid `rsync --delete`. Subdirectory apps must set Vite `base: './'` — without it `index.html` requests `/assets/...` from the site root and the page loads blank (hit gapp-form). After rsync, `orwa.org` may serve the old `index.html` for up to ~10 min (`cache-control: max-age=600` + Cloudflare); verify with `curl -s https://orwa.org/<app>/ | grep -o 'index\.[a-f0-9]*\.js'` until the new hash appears (`wp cache flush` only clears object cache, not page/CDN cache). The README's `npm run deploy` reference is stale.
- CRITICAL frontend-build pitfall: `nx build <app>` auto-loads the app's tracked `.env` (with `VITE_API_ENDPOINT=http://localhost:1337`) into `process.env` before invoking vite, and OS-level env vars take priority over `.env.production` — so `nx build` silently bakes localhost into production bundles even though a direct `npx vite build` in the app dir is correct (this shipped a broken member-manager login on 2026-07-16). member-manager's dev env was renamed to `.env.development` (vite dev still loads it; nx no longer injects it). Other apps still have the trap: build them with `npx vite build` from the app dir or rename their `.env` too, and ALWAYS `grep -c 'localhost:1337' dist/assets/*.js` before rsyncing.
- Local dev Strapi (`apps/strapi/.env`) connects to MySQL on port 3307 (container `orwa-mig-mysql`, database `strapi_prod` — a migration copy of production), NOT the docker-compose MySQL on 3306. Production DB is MySQL in the `nextcloud-mysql` container (network `db_db`, database `strapi_prod_v5`). Local Strapi uses `PORT=13370` because Windows Hyper-V/WSL reserved TCP ranges make ports like 1337–1339 bind with `EADDRINUSE` even when no WSL process listens (`ss` shows nothing); Windows-side `Cursor.exe` can likewise hold frontend ports (e.g. 4201/4203), making vite dev servers silently hop to a neighboring port and serve the wrong app. Vite frontends do not read `apps/strapi/.env` — each app's own `VITE_API_ENDPOINT` must match the Strapi port. Path convention varies: member-manager uses the host root and appends `/api` in code; conference-registration and `@orwa/terms-gate` expect `VITE_API_ENDPOINT` to already end with `/api` (omitting it 404s content-type routes).
- The repo recently migrated Strapi v4 -> v5. A `global::numeric-id-compat` middleware (`apps/strapi/src/middlewares/numeric-id-compat.ts`) rewrites numeric entity ids in URLs and numeric relation ids in request bodies to documentIds, and strips unknown body keys; body rewriting requires it to be registered after `strapi::body` in `config/middlewares.ts`. Strapi 5 rejects unknown body fields with 400 "Invalid key ..." (v4 silently stripped them), returns `null` (not `undefined`) for empty media/relation/component fields — guard with `!= null` and normalize empty arrays to `[]` in forms — and omits ALL relation/media fields from PUT/POST responses unless the write URL itself has `populate` (v4 included them). react-admin merges the write response into the cached record (`{...old, ...new}`) and resets forms from it, so a bare write response silently reverts relation inputs — and a second save then wipes them in the DB. member-manager's data provider sends `?populate=*` on update/create for this reason.
- member-manager data provider (`apps/member-manager/src/helpers/ra-strapi-data-provider`): remaps every record `id` → Strapi `documentId` and keeps the numeric PK as `entityId` (also recursively on nested populated content-type rows). **List filters:** `convertRaParamsToStrapiParams` / `serializeStrapiFilters.ts` rewrites documentId-shaped leaves (`/^[a-z0-9]{16,64}$/`) to `filters[rel][documentId]=…` (and `filters[id]` → `filters[documentId]`), so call sites can pass `record.id` without empty lists. Bare `filters[rel]=<documentId>` still returns 0 rows at the API; numeric bare filters still work. Prefer `record.id` in filters; use `getRelationFilterId` / `entityId` (`src/helpers/strapiIds.ts`) when you intentionally need a numeric value; never `parseInt(documentId)` (→ `NaN`). Other ORWA frontends do not share this provider and mostly keep numeric ids.
- member-manager's grant dashboard can fan out hundreds of parallel `getOne ?populate=*` requests, which can overload the server and surface as `net::ERR_FAILED` in the browser (not CORS). Conference Manager mounts all tab panels at once, so Extras/Tickets API noise on the Edit tab is often unrelated to the bug under investigation. Shared Datagrid zebra striping (`customDatagridStyle` in `apps/member-manager/src/css/index.ts`) hardcoded light stripes and overrides per-row `sx` — a recurring dark-mode culprit; module folder names have quirks (emails module is `modules/emails-magement`, memberships is `modules/memberships_v2`).
- conference-registration reads `VITE_API_ENDPOINT` and API key from `.env.production` (production API is `https://admin.orwa.org/api`); the dev `.env` key gets 401s against production. Build/serve with `--mode production` when testing against production data (and deploy with `npx vite build` from the app dir — not `nx build`, which can bake localhost). Resubmit flows can carry orphan extra/ticket IDs from another conference — coerce id/documentId shapes and skip missing extras (otherwise UI shows `$NaN`). Presence-only `?admin` opens Admin Login; after sign-in use profile menu → Enable Admin View to register when the conference is closed (Conference Status override is there too). Tailwind v4 must `@source` `mj-react-form-builder`'s dist in `src/index.css` or library utilities (e.g. FileInput `col-span-5/7`) never generate and the upload UI collapses. Checkout collects distinct billing email and billing phone (`paymentData.billingAddress`; Authorize.net/Strapi); confirmation emails list Billing Email/Phone separately from registrant POC.
- conference-registration wizard state survives refresh/HMR and back-button: `helpers/wizardPersistence.ts` keeps a sessionStorage form draft (card/logo fields stripped; cleared on successful submit) and `WizardStateSync` mirrors the step into `?step=<key>` via `history.replaceState` while preserving `admin`/`conference_id`/`source`; the Enable Admin View toggle persists too — don't regress these when touching steps. Booths: booths without extras add/remove inline with no modal, only booths with extras open a TicketModal-style modal (`helpers/boothHasExtras.ts`); base pricing lives in `helpers/boothBasePrice.ts` — first booth uses `booth_price`, additional booths use `booth_price_2` only when positive, otherwise fall back to `booth_price` ($0 booths are never valid); `purchasable_booths` is the per-checkout booth max (enforced in AddBoothsComponent), not total conference inventory. Contestants step auto-appears when Contestant-context tickets exist (Golfer/Fisher/Contestant; optional to skip); Water Taste Test remains Annual Contestant-addon gated. UI is Participants-only (heading "Add Contestant"); the modal is driven by Conference Manager ticket types/prices (Already-Registered vs Contestant-Only), not hard-coded golf-vs-fishing copy. Reduced-price path must select an existing same-conference Attendee/Vendor registration and then a person on that registration (populate hidden fields from the parent — org-only selection enables price abuse); standalone-price purchases create unique Contestant registrations. Mulligans and similar are per-contestant quantity extras (min–max stepper, not boolean) gated via `filterVisibleExtras`; Strapi webhooks route `context: "Contestant"` tickets into `conference-contestant` records.
- Grant application edit flow (Strapi grant-application API): `POST /grant-application/request-edit` emails a tokenized link and responds `not_found`/`locked`/`sent`; `GET`/`PUT /grant-application/edit-session?token=` re-validate token AND status on every load/save — only status "New Application" is editable, tokens live in private schema fields `edit_token`/`edit_token_expires` (30-day expiry, also issued on create), status/`application_id`/application date can never change via edit, and the email lookup matches any contact (point of contact, chairman, engineer, `additional_contacts` oneToMany). Grant financial reporting attributes payouts to the fiscal year of the application's approval (`committee_date`), NOT the payout `transaction_date` (admin payouts with no application stay on transaction date); "Previous FY Rollover" (`grants/helpers/previousFyRollover.ts`) chains unawarded allocation + closeout returns across prior FYs so Funds Still Available reconciles instead of going negative. The statuses actually present in the DB are fewer than the schema enum suggests: "Awaiting Signature", "Withdrawn", "Tabled Application", and the denial variants do NOT exist as real statuses — the pathways dimensional model (`grant-manager/grants/components/summary/pathways/model.ts`) derives "Needing/Awaiting Signature" as approved-but-not-yet-"Grant Agreement Signed/Sealed/Returned" and consolidates Denied/Withdrawn into one segment.
- Changes to Strapi content-type schemas regenerate `apps/strapi/types/generated/contentTypes.d.ts` (commit alongside). The activity-feed plugin (`apps/strapi/src/plugins/activity-feed`) compiles server TypeScript with `npx tsc -p tsconfig.server.json` from the plugin directory; lifecycle hooks must null-guard relation lookups and tolerate Strapi 5 shapes like `{ set: [...] }` in `event.params.data`.
- Terms: Strapi `term` collection (`title`, `slug`, `identifiers[]`, `content`) managed via member-manager Terms Manager; shared `@orwa/terms-gate` (`libs/terms-gate`) provides a locking overlay with scroll-to-enable Agree. Identifier `Global` is always queried unless `global={false}`; empty matches + `global={false}` is a no-op. Host apps that set `#root { text-align: center }` must not force that onto terms body HTML — rich-text alignment from the editor should win.
- `npx nx serve <app>` can hang when its output is piped; running the app's vite binary directly with an explicit port is more reliable for headless testing. `scripts/interactive-dev.js` (`pnpm dev`) should kill the prior session tree and orphaned serve/vite/strapi processes (and free configured ports) before starting so restarts do not leave orphans (`node_modules/.cache/interactive-dev.pid`); it must also pass `--parallel=<selected apps + 3>` to `nx run-many` — Nx defaults to 3 threads and continuous serve tasks never finish, so extra tasks starve forever on "Waiting for available thread" (starved `strapi:serve` = frontends up but every API call "Failed to fetch"). Nx's `@nx/vite:dev-server` executor can also generate a broken fs allow list (`apps/<app>/apps/<app>`) so Vite 403s every asset (blank/black page); the fix pattern is a `serve` target using `nx:run-commands` running the app's `npm run dev` with `server.fs.allow: ['../..']`. Most apps use `strictPort: true` so port steals fail loudly, but grant-map deliberately uses `strictPort: false` (user request: Windows Cursor.exe permanently holds 4203, so it hops — read the vite startup output for the actual port). member-manager's theme persists in localStorage key `RaStore.theme` — set it to `dark` and reload to force dark mode in headless checks; parallel agents contend over the shared Playwright MCP session, so use isolated browser contexts or a dedicated Chrome DevTools page per agent. To log into member-manager headlessly, create a temporary user directly in local MySQL (bcrypt-hashed password, role 13) and delete it after verifying.
