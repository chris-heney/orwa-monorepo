# AGENTS.md

## Learned User Preferences

- When asked to "stage/commit/push/deploy", commit only the changes relevant to the request; leave unrelated in-progress work unstaged and keep test artifacts (`.playwright-mcp/`, screenshots, editor state files) out of version control.
- Group uncommitted work into small logical commits with scoped prefixes, e.g. `strapi: ...`, `member-manager: ...`, `associate: add "Drone Cleaning" to category enum`.
- "Deploy" implicitly includes the server-side step (pull + restart on the production host, or rsync for frontends), not just pushing the image/bundle.
- Verify frontend changes visually in a headless browser before deploying; a clean typecheck/build alone is not sufficient.
- Non-destructive production smoke tests after deploy are welcome (e.g. re-sending a previously failing request with unchanged business values).
- member-manager login must not hard-fail when user metadata/role fetch fails after a successful JWT auth; fall back to a safe default (e.g. Guest) so users can still get in.
- Do not commit tracked `.env` files that contain secrets (e.g. Mapbox tokens in `grant-map`); GitHub push protection rejects them. Leave secret-bearing and machine-local port/API env tweaks unstaged when they would re-push secret blobs.
- Do not wrap member-manager / Conference Manager admin surfaces with `TermsGate`; terms acceptance belongs on public registration (and similar) flows only.
- New member-manager list/edit pages should use the Media Library–style black `PageHeadingBar` (actions in the bar; Contact-style Back on create/edit), as on Terms and Asset Manager.
- conference-registration sponsorship must be its own wizard step immediately before Billing (not a Type-page toggle); people miss a buried sponsor control. Sponsorships are available to Attendee and Vendor (online when packages exist).
- conference-registration validation must be unmissable (user base skews older): use the shared red toast for step-validation failures everywhere and visibly highlight the invalid fields (light red background or a bold red rounded outline). Grey option wraps around checkboxes/radios must behave like labels — fully clickable, pointer cursor, subtle darker hover.
- In conference-registration TicketModal, Registration Options (Training Type) sits above Contact Details; any training type other than None requires a real email — clear/hide/disable "I do not have an email", and note that email is required for training credit.

## Learned Workspace Facts

- Strapi backend deploy: `npx nx run strapi:docker-push` (builds and pushes image to GHCR), then `ssh root@admin.orwa.org "cd /var/opt/orwa-monorepo && docker compose pull strapi && docker compose up -d strapi"`. The live compose file is `/var/opt/orwa-monorepo/docker-compose.yml` (not `/var/opt/admin.orwa.org`); the production Strapi container is named `orwa-admin-v5`.
- Frontends (member-manager, conference-registration, etc.) deploy as static production bundles rsynced over SSH to WP Engine (`orwa.ssh.wpengine.net`, install `orwa`), e.g. `sites/orwa/conference-registration/` serves orwa.org/conference-registration. Avoid `rsync --delete`. After rsync, `orwa.org` may serve the old `index.html` for up to ~10 min (`cache-control: max-age=600` + Cloudflare); verify with `curl -s https://orwa.org/<app>/ | grep -o 'index\.[a-f0-9]*\.js'` until the new hash appears (`wp cache flush` only clears object cache, not page/CDN cache). The README's `npm run deploy` reference is stale.
- CRITICAL frontend-build pitfall: `nx build <app>` auto-loads the app's tracked `.env` (with `VITE_API_ENDPOINT=http://localhost:1337`) into `process.env` before invoking vite, and OS-level env vars take priority over `.env.production` — so `nx build` silently bakes localhost into production bundles even though a direct `npx vite build` in the app dir is correct (this shipped a broken member-manager login on 2026-07-16). member-manager's dev env was renamed to `.env.development` (vite dev still loads it; nx no longer injects it). Other apps still have the trap: build them with `npx vite build` from the app dir or rename their `.env` too, and ALWAYS `grep -c 'localhost:1337' dist/assets/*.js` before rsyncing.
- Local dev Strapi (`apps/strapi/.env`) connects to MySQL on port 3307 (container `orwa-mig-mysql`, database `strapi_prod` — a migration copy of production), NOT the docker-compose MySQL on 3306. Production DB is MySQL in the `nextcloud-mysql` container (network `db_db`, database `strapi_prod_v5`). Local Strapi uses `PORT=13370` because Windows Hyper-V/WSL reserved TCP ranges make ports like 1337–1339 bind with `EADDRINUSE` even when no WSL process listens (`ss` shows nothing); Windows-side `Cursor.exe` can likewise hold frontend ports (e.g. 4201/4203), making vite dev servers silently hop to a neighboring port and serve the wrong app. Vite frontends do not read `apps/strapi/.env` — each app's own `VITE_API_ENDPOINT` must match the Strapi port. Path convention varies: member-manager uses the host root and appends `/api` in code; conference-registration and `@orwa/terms-gate` expect `VITE_API_ENDPOINT` to already end with `/api` (omitting it 404s content-type routes).
- The repo recently migrated Strapi v4 -> v5. A `global::numeric-id-compat` middleware (`apps/strapi/src/middlewares/numeric-id-compat.ts`) rewrites numeric entity ids in URLs and numeric relation ids in request bodies to documentIds, and strips unknown body keys; body rewriting requires it to be registered after `strapi::body` in `config/middlewares.ts`. Strapi 5 rejects unknown body fields with 400 "Invalid key ..." (v4 silently stripped them), returns `null` (not `undefined`) for empty media/relation/component fields — guard with `!= null` and normalize empty arrays to `[]` in forms — and omits ALL relation/media fields from PUT/POST responses unless the write URL itself has `populate` (v4 included them). react-admin merges the write response into the cached record (`{...old, ...new}`) and resets forms from it, so a bare write response silently reverts relation inputs — and a second save then wipes them in the DB. member-manager's data provider sends `?populate=*` on update/create for this reason.
- member-manager's custom data provider still addresses Strapi entries by numeric id; its grant dashboard fans out hundreds of parallel `getOne ?populate=*` requests, which can overload the server and surface as `net::ERR_FAILED` in the browser (not CORS, not the documentId change). Conference Manager mounts all tab panels at once, so Extras/Tickets API noise on the Edit tab is often unrelated to the bug under investigation.
- conference-registration reads `VITE_API_ENDPOINT` and API key from `.env.production` (production API is `https://admin.orwa.org/api`); the dev `.env` key gets 401s against production. Build/serve with `--mode production` when testing against production data (and deploy with `npx vite build` from the app dir — not `nx build`, which can bake localhost). Resubmit flows can carry orphan extra/ticket IDs from another conference — coerce id/documentId shapes and skip missing extras (otherwise UI shows `$NaN`). Presence-only `?admin` opens Admin Login; after sign-in use profile menu → Enable Admin View to register when the conference is closed (Conference Status override is there too). Tailwind v4 must `@source` `mj-react-form-builder`'s dist in `src/index.css` or library utilities (e.g. FileInput `col-span-5/7`) never generate and the upload UI collapses.
- conference-registration wizard state survives refresh/HMR and back-button: `helpers/wizardPersistence.ts` keeps a sessionStorage form draft (card/logo fields stripped; cleared on successful submit) and `WizardStateSync` mirrors the step into `?step=<key>` via `history.replaceState` while preserving `admin`/`conference_id`/`source`; the Enable Admin View toggle persists too — don't regress these when touching steps. Booths: booths without extras add/remove inline with no modal, only booths with extras open a TicketModal-style modal (`helpers/boothHasExtras.ts`); base pricing lives in `helpers/boothBasePrice.ts` — first booth uses `booth_price`, additional booths use `booth_price_2` only when positive, otherwise fall back to `booth_price` ($0 booths are never valid); `purchasable_booths` is the per-checkout booth max (enforced in AddBoothsComponent), not total conference inventory.
- Grant application edit flow (Strapi grant-application API): `POST /grant-application/request-edit` emails a tokenized link and responds `not_found`/`locked`/`sent`; `GET`/`PUT /grant-application/edit-session?token=` re-validate token AND status on every load/save — only status "New Application" is editable, tokens live in private schema fields `edit_token`/`edit_token_expires` (30-day expiry, also issued on create), status/`application_id`/application date can never change via edit, and the email lookup matches any contact (point of contact, chairman, engineer, `additional_contacts` oneToMany). Grant financial reporting attributes payouts to the fiscal year of the application's approval (`committee_date`), NOT the payout `transaction_date` (admin payouts with no application stay on transaction date); "Previous FY Rollover" (`grants/helpers/previousFyRollover.ts`) chains unawarded allocation + closeout returns across prior FYs so Funds Still Available reconciles instead of going negative.
- Changes to Strapi content-type schemas regenerate `apps/strapi/types/generated/contentTypes.d.ts` (commit alongside). The activity-feed plugin (`apps/strapi/src/plugins/activity-feed`) compiles server TypeScript with `npx tsc -p tsconfig.server.json` from the plugin directory; lifecycle hooks must null-guard relation lookups and tolerate Strapi 5 shapes like `{ set: [...] }` in `event.params.data`.
- Terms: Strapi `term` collection (`title`, `slug`, `identifiers[]`, `content`) managed via member-manager Terms Manager; shared `@orwa/terms-gate` (`libs/terms-gate`) provides a locking overlay with scroll-to-enable Agree. Identifier `Global` is always queried unless `global={false}`; empty matches + `global={false}` is a no-op. Host apps that set `#root { text-align: center }` must not force that onto terms body HTML — rich-text alignment from the editor should win.
- `npx nx serve <app>` can hang when its output is piped; running the app's vite binary directly with an explicit port is more reliable for headless testing. `scripts/interactive-dev.js` should kill the prior session tree and orphaned serve/vite/strapi processes (and free configured ports) before starting so restarts do not leave orphans (`node_modules/.cache/interactive-dev.pid`). Nx's `@nx/vite:dev-server` executor can also generate a broken fs allow list (`apps/<app>/apps/<app>`) so Vite 403s every asset (blank/black page); the fix pattern (applied to member-manager, grant-map, grant-scoring, conference-registration) is a `serve` target using `nx:run-commands` running the app's `npm run dev`, with `server.fs.allow: ['../..']` and `strictPort: true` so port steals fail loudly instead of reshuffling.
